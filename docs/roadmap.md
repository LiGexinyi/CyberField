# CyberField 三周开发计划
> 时间：2026-11-07 → 2026-11-28　|　目标：多源采集 + 可视化分析平台

---

## 一、目标

1. **多平台接入**：先打通简单合规源，后续扩展全部平台
2. **可视化界面**：本地 Web 仪表盘（FastAPI + ECharts）
3. **核心分析**：
   - 时间线梗演化（关键词热度时序）
   - 使用群体画像（平台/作者/关键词分布、聚类）
   - 相关同时出现的话题（共现网络）
   - 每天讨论度 + 火的时间（峰值检测）
   - 各方态度（预训练中文情感模型）
4. **用户管理**：用户自己提供平台登录账号 → 注册/登录 + 平台账号凭据安全存储
5. **大模型扩展预留**：后续可接入 LLM 做深度分析（梗演化叙事、态度总结、趋势预测等）

---

## 二、总体架构

```
┌───────────── 浏览器（用户操作）─────────────┐
│  总览 / 时间线 / 共现网络 / 群体 / 态度 / 讨论度 │
└────────────────────┬────────────────────┘
                     │ HTTP
                     ▼
┌─────────────── FastAPI 后端 ──────────────────┐
│  user/      用户注册/登录、会话、平台账号管理    │
│  collect/   采集调度（任务触发、容错、去重）     │
│  analysis/  分析引擎（时间线/共现/群体/讨论度/态度）│
│  llm/       LLM 分析服务（抽象接口，预留）       │
│  api/       各模块的 REST 接口                 │
└────────────────────┬─────────────────────────┘
                     │
                     ▼
┌────────────── 存储层 ────────────────────────┐
│  SQLite（数据表 + FTS5 全文检索）               │
│  平台凭据加密存储（每用户隔离）                  │
└────────────────────┬─────────────────────────┘
                     │ 子进程 / HTTP
                     ▼
        采集源：MediaCrawler / 合规 MCP（zhihu-search、weibo-mcp）
```

**LLM 预留设计**：`analysis/llm.py` 定义 `LLMProvider` 接口，实现本地（Ollama/transformers）与 API（OpenAI 兼容）两种实现，界面配置切换；后续分析场景通过该接口扩展，不动现有分析管线。

## 三、技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | FastAPI + Uvicorn | 异步、自带文档 |
| 前端 | HTML/JS + ECharts（本地引入） | 图表齐全：折线/柱/网络/热力/词云 |
| 存储 | SQLite + FTS5 | 已有基础，加全文检索 |
| 分词 | jieba | 中文关键词提取 |
| 情感分析 | HuggingFace `transformers` + 中文 roberta 情感模型 | 预训练模型版 |
| 用户认证 | JWT + 密码哈希（passlib/bcrypt） | 会话管理 |
| 凭据加密 | cryptography（Fernet）+ 系统级密钥 | 平台 Cookie 安全存储 |
| LLM（预留） | `LLMProvider` 抽象：Ollama / OpenAI 兼容 API | 后续扩展 |

## 四、数据模型（新增表）

```sql
-- 用户
users(id, username UNIQUE, password_hash, created_at)

-- 平台账号凭据（每用户，加密存储，仅本人可见）
platform_credentials(id, user_id, platform, nickname, encrypted_cookie,
                     status, created_at, updated_at)

-- 采集任务（增量/定时）
collect_tasks(id, user_id, keyword, platforms, status, started_at, finished_at)

-- 采集帖子（已有 collected_posts 表，扩充分析字段）
collected_posts(id, user_id, keyword, platform, title, text, url, author,
                published_at, source_adapter, fetched_at, likes, comments,
                shares, collected, tags)   -- 新增 user_id / 互动数 / 标签

-- 分析结果缓存（可选，加速重复查看）
analysis_cache(id, user_id, analysis_type, params, result_json, created_at)
```

> 兼容性：现有 `collected_posts` 表增加列时用 `ALTER TABLE` 迁移；`user_id` 为空视为"共享/演示数据"，老数据不丢失。
